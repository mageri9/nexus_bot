# 📡 Nexus (v2.0)

> **Nexus** — событийно-ориентированная платформа управления (Control Plane), наблюдаемости на уровне приложений (Application Observability) и автоматической ИИ-диагностики (AIOps) для экосистемы Telegram-ботов и микросервисов на вашем VPS.

Система разделена на слабосвязанные слои, работает по паттерну DooD (Docker-out-of-Docker) и использует Redis в качестве шины Pub/Sub, кэша состояний и базы дедупликации ошибок, обеспечивая мгновенный отклик интерфейса и нулевое влияние на производительность хоста.

### Ключевые компоненты платформы (v2.0)

1. **Непрерывный стриминг логов (Log Ring Buffer):** Фоновая служба `LogCollector` постоянно слушает вывод контейнеров через `docker logs -f` и пишет их в Redis-списки с автоматическим усечением `LTRIM` (хранится последние 100 строк). Это гарантирует мгновенный доступ к логам SRE-ассистента и UI-интерфейса за $O(1)$ без обращения к Docker CLI, а также сохранение логов непосредственно перед падением.
2. **Многофреймворковый `nexus_sdk`:** Готовый легковесный пакет для интеграции наблюдаемости в ваших ботов. Нативно поддерживает как **`aiogram`**, так и **`python-telegram-bot`**.
3. **Виртуальный пульс (Heartbeat):** Бот через SDK шлет сигналы `app:heartbeat` каждые 15 секунд. Виртуальный ресурс `ApplicationHeartbeat` в ядре проверяет время затухания пульса в Redis [1, 2]. Если бот зависнет или отключится, система зафиксирует это как `unhealthy` и заведет инцидент.
4. **Унифицированный классификатор сигналов (`Classifier`):** Промежуточный слой, преобразующий любые события (сбои контейнеров, DevOps-деплои, системные ошибки ботов из SDK) в единый формат `Signal` [1, 2]. Централизует проверку режимов обслуживания, определение уровней критичности (`HIGH`, `MEDIUM`, `INFO` и т.д.) и подавление ложных срабатываний.
5. **Реестр ошибок и дедупликация (Error Registry):** При получении трейсбэка ошибки из SDK система отсекает служебные фреймы фреймворков и вычисляет уникальный `fingerprint` ошибки (на основе первого non-framework фрейма). Ошибка логируется в хэш-таблицу в Redis с увеличением счетчика повторений (`count`), фиксацией времени активности и флага `resolved`.
6. **Авто-восстановление приложений (Auto-Recovery):** Если инцидент уровня приложения (`app:error`) открыт, но повторные ошибки с этим фингерпринтом не фиксируются в течение `APP_ERROR_AUTO_RECOVERY_THRESHOLD` секунд (по умолчанию 60с), коллектор автоматически закрывает инцидент с фиксацией общего времени простоя.
7. **История и тренды здоровья (Health Time-Series):** На каждом тике коллектор вычисляет Health Score агентов и фиксирует их во временной ряд в Sorted Set в Redis (ротация последних 100 замеров). На основе двух последних замеров вычисляется визуальный индикатор динамики здоровья: рост `📈`, падение `📉` или стабильность `➡️`.
8. **DooD через изолированный прокси:** Ядро не монтирует напрямую сокет Docker. Запросы идут через `docker-socket-proxy`, который разрешает только безопасный whitelist методов (`inspect`, `stats`, `logs`, `restart`) и блокирует критические (например, `exec`).

## 💻 Интеграция `nexus_sdk` в ваших ботов

Интеграция занимает несколько строк в файле инициализации/запуска вашего бота.

### Вариант А. Бот на фреймворке `aiogram` (v3)
```python
import asyncio
from aiogram import Bot, Dispatcher
from nexus_sdk import NexusSDK

bot = Bot(token="TOKEN")
dp = Dispatcher()

# Инициализируем SDK
nexus = NexusSDK(
    endpoint_url="http://nexus-webhook:8000/events/app",
    app_secret="ТВОЙ_NEXUS_APP_SECRET",
    project_name="my_aiogram_bot" # Строго совпадает с именем агента в манифестах
)

# 1. Подключаем глобальный перехватчик ошибок
nexus.register_aiogram_error_handler(dp)

# 2. Запускаем периодическую отправку пульса (Heartbeat) раз в 15 секунд
nexus.start_heartbeat(interval_seconds=15)

async def main():
    try:
        await dp.start_polling(bot)
    finally:
        await nexus.close() # Грациозно останавливаем сессию SDK при остановке бота

if __name__ == "__main__":
    asyncio.run(main())
```

### Вариант Б. Бот на фреймворке `python-telegram-bot` (v20+)
```python
from telegram.ext import Application
from nexus_sdk import NexusSDK

app = Application.builder().token("TOKEN").build()

# Инициализируем SDK
nexus = NexusSDK(
    endpoint_url="http://nexus-webhook:8000/events/app",
    app_secret="ТВОЙ_NEXUS_APP_SECRET",
    project_name="my_ptb_bot"
)

# 1. Подключаем глобальный перехватчик ошибок PTB
nexus.register_ptb_error_handler(app)

# 2. Запускаем периодическую отправку пульса (Heartbeat)
nexus.start_heartbeat(interval_seconds=15)

def main():
    # Настройка хендлеров...
    try:
        app.run_polling()
    finally:
        # Закрываем сессию SDK при остановке приложения
        import asyncio
        loop = asyncio.get_event_loop()
        if loop.is_running():
            loop.create_task(nexus.close())
        else:
            loop.run_until_complete(nexus.close())
```

## 🔒 Модель безопасности

* **Фильтрация доступа:** Все управляющие команды, а также интерактивные inline-действия (Restart, Logs, AI Diagnose, Silence) защищены фильтром `IsAdmin` как на уровне сообщений, так и на уровне callback-запросов.
* **Безопасность Webhook-приемника:** Все входящие запросы принимаются только при наличии валидной HMAC-SHA256 подписи в заголовках. Для GitHub-вебхуков используется `GITHUB_WEBHOOK_SECRET`, для приложений-клиентов через SDK — `NEXUS_APP_SECRET` [2]. Отсутствие подписи или несовпадение ключа прерывают обработку на раннем этапе (fail-closed).
* **Сетевая изоляция:** Сервис вебхуков принимает входящие сигналы от ботов исключительно внутри приватной Docker-сети `nexus_shared` на хосте VPS, не открывая порты во внешний мир.

## 📊 Математика расчета Health Score (0–100%)

Показатель здоровья агента рассчитывается динамически на каждом тике:
* **Стартовый баланс:** `100` баллов.
* **Сбой ресурса** (`status != running/healthy`): `-50` баллов за каждый упавший компонент.
* **Критическая утилизация CPU** (>95%): `-15` баллов.
* **Критическая утилизация RAM** (>90%): `-15` баллов.
* **Каждый перезапуск контейнера** (`RestartCount`): `-5` баллов.
* **Сбой критических СУБД** (redis, postgres): дополнительный штраф `-20` баллов.

## 📡 Управление инцидентами в Telegram

* **`🔄 Restart`** — ручной перезапуск упавшего контейнера.
* **`📝 Logs`** — мгновенное извлечение последних строк кольцевого буфера логов из Redis.
* **`🧠 AI Diagnose`** — запуск ручного ИИ-анализа по агрегированному контекстному бандлу ошибки.
* **`🔕 Silence 1h`** — перевод алертов по ресурсу в режим тишины на 1 час (защита от спама при циклическом падении).

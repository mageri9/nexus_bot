# 📡 Nexus

> **Nexus** — это расширяемое событийно-ориентированное ядро управления (Control Plane) и мониторинга для экосистемы Telegram-ботов и микросервисов. 

В отличие от традиционных DevOps-панелей, Nexus разделяет логику интерфейса и инфраструктуры, обеспечивая мгновенный отклик (опрос за <10 мс) и интеллектуальную диагностику инцидентов с помощью ИИ.

---

## 🏗️ Архитектура системы

Nexus построен на принципах слабой связности компонентов, декларативного описания ресурсов и разделения операций чтения/записи (CQS).

```text
                  Telegram (aiogram 3)
                           │
                     Query / Command
                           │
             ┌─────────────┴─────────────┐
             ▼                           ▼
       QueryService               CommandService
      (Redis Cache)               (Event Bus)
             ▲                           │
             │                           ▼
      StateCollector              [ action:success ]
       (Bg Ticker)                       │
             │                           ▼
             └───────────┐        TelegramNotifier
                         │               │
                         ▼               ▼
                   Project Agents ◄──────┘
                         │
                     Resources (Docker, Disk, etc.)
                         │
                     Transport (LocalShell / SSH)

Ключевые компоненты:

1.  Transport Layer — абстракция выполнения системных вызовов. Полностью
    изолирует ресурсы от хоста. Позволяет легко переключаться между локальным
    терминалом и SSH-сессиями.
2.  Declarative Resources — строго типизированные объекты (контейнеры, диски,
    базы данных), управляемые через явные методы (restart(), get_logs()) вместо
    громоздких ветвлений if-else.
3.  Project Agents — паспорта проектов. Декларативно группируют ресурсы каждого
    бота (например, ImageBot = Docker + Disk) и опрашивают их строго параллельно
    через asyncio.gather.
4.  State Collector & Redis Cache — фоновый асинхронный процесс, который
    опрашивает агентов раз в 5 секунд и кэширует состояние в Redis. Telegram-бот
    мгновенно забирает готовый JSON-слепок из памяти.
5.  Event Bus — шина событий. Полностью разрывает связность между выполнением
    команд и уведомлениями. Любое действие генерирует событие, на которое
    независимо подписываются нотификаторы.
6.  AI Diagnostic (AITUNNEL) — при запросе от админа ИИ-ассистент (на базе
    Google Gemma 4) анализирует текущий кэш системы и автоматически считывает
    логи упавших контейнеров, выдавая точный диагноз инцидента.

📂 Структура проекта

nexus/
├── agents/             # Декларативные манифесты проектов (агенты)
├── config/             # Конфигурация и валидация переменных (pydantic-settings)
├── core/               # Ядро системы (базовые контракты Resource, Agent, Registry)
├── infra/              # Реализация ресурсов (Docker, Disk)
├── services/           # Бизнес-логика (QueryService, CommandService, Collector, AI)
├── telegram/           # Тонкий Telegram-интерфейс (aiogram 3, фильтры, нотификаторы)
├── transports/         # Реализация выполнения команд (LocalShell, SSH)
├── main.py             # Точка входа в приложение
└── requirements.txt    # Зависимости проекта

🚀 Быстрый старт

1. Подготовка окружения

Убедитесь, что на целевой машине запущен Redis:

docker run -d --name nexus-redis -p 6379:6379 redis

Для тестирования управления контейнерами запустите тестовый сервис:

docker run -d --name nexus-test alpine sleep 1000

2. Установка зависимостей

Клонируйте проект и установите пакеты внутри виртуального окружения:

python -m venv .venv
source .venv/bin/activate  # Для Windows: .venv\Scripts\activate
pip install -r requirements.txt

3. Конфигурация (.env)

Создайте файл .env в корневой директории:

BOT_TOKEN=12345678:YourTelegramBotToken
REDIS_URL=redis://localhost:6379/0
DEBUG=True
ADMIN_IDS=1054280714
AITUNNEL_API_KEY=sk-aitunnel-yourKeyHere

4. Запуск

python main.py

📡 Список доступных команд

Администрирование полностью защищено фильтром IsAdmin и доступно только
пользователям из списка ADMIN_IDS:

  - /start — Инициализация сессии управления.
  - /status — Получение моментального ASCII/HTML отчета о состоянии всех систем.
    Под отчетом автоматически выводятся инлайн-кнопки действий для управления
    ресурсами.
  - Любой текстовый запрос (например: «Что не так с имиджботом?») — запускает
    ИИ-диагностику логов контейнера и метрик.

🛠️ Расширение системы

Добавление нового проекта в общую экосистему Nexus занимает ровно 1 минуту без
изменения кода ядра:

1.  Опишите ресурсы в agents/manifest.py:

my_new_bot = ProjectAgent(
    name="my_bot",
    resources={
        "app": DockerContainer("app", local_transport, "my-bot-container"),
        "storage": DiskResource("storage", local_transport, "/data/my_bot")
    }
)

2.  Зарегистрируйте его в agents/__init__.py:

registry.register(my_new_bot)

Система автоматически начнет собирать метрики нового бота, выводить его в
/status, генерировать инлайн-кнопки перезапуска и скармливать его логи
искусственному интеллекту в случае падений.

# 📡 Nexus (v2.0)

> **Nexus** — событийно-ориентированная платформа управления (Control Plane), наблюдаемости на уровне приложений (Application Observability) и автоматической ИИ-диагностики (AIOps) для экосистемы Telegram-ботов и микросервисов на вашем VPS.

Система разделена на слабосвязанные слои, работает по паттерну DooD (Docker-out-of-Docker) и использует Redis в качестве шины Pub/Sub, кэша состояний и базы дедупликации ошибок, обеспечивая мгновенный отклик интерфейса и нулевое влияние на производительность хоста.

### Ключевые компоненты платформы (v2.0)

1. **Непрерывный стриминг логов (Log Ring Buffer):** Фоновая служба `LogCollector` постоянно слушает вывод контейнеров через `docker logs -f` и пишет их в Redis-списки с автоматическим усечением (хранится последние 100 строк). Это гарантирует мгновенный доступ к логам для UI-интерфейса и AI-диагностики без обращения к Docker CLI, а также сохраняет контекст непосредственно перед падением — а не только то, что осталось в буфере stdout контейнера к моменту, когда инцидент уже открыт.
2. **Многофреймворковый `nexus_sdk`:** Готовый легковесный пакет для интеграции наблюдаемости в ваших ботов. Нативно поддерживает как **`aiogram`**, так и **`python-telegram-bot`**.
3. **Виртуальный пульс (Heartbeat):** Бот через SDK шлёт сигналы `app:heartbeat` каждые 15 секунд. Виртуальный ресурс `ApplicationHeartbeat` в ядре проверяет время затухания пульса в Redis. Если бот зависнет или отключится (даже если процесс контейнера формально жив), система зафиксирует это как `unhealthy` и заведёт инцидент — класс отказов, недостижимый через одну лишь проверку статуса контейнера.
4. **Унифицированный классификатор сигналов (`Classifier`):** Промежуточный слой, преобразующий любые события (сбои контейнеров, DevOps-деплои, ошибки приложений из SDK) в единый формат `Signal`. Централизует проверку режима техобслуживания, определение уровней критичности (`HIGH`, `MEDIUM`, `INFO` и т.д.) и подавление ложных срабатываний.
5. **Реестр ошибок и дедупликация (Error Registry):** При получении трейсбэка ошибки из SDK система отсекает служебные фреймы фреймворков и вычисляет уникальный `fingerprint` ошибки (на основе первого non-framework фрейма). Ошибка логируется в хэш-таблицу в Redis с увеличением счётчика повторений, фиксацией времени активности и статуса.
6. **Авто-восстановление приложений (Auto-Recovery):** Если инцидент уровня приложения (`app:error`) открыт, но повторные ошибки с этим fingerprint не фиксируются в течение `APP_ERROR_AUTO_RECOVERY_THRESHOLD` секунд (по умолчанию 60с), коллектор автоматически закрывает инцидент с фиксацией общего времени простоя.
7. **История и тренды здоровья (Health Time-Series):** На каждом тике коллектор вычисляет Health Score агентов и фиксирует их во временной ряд в Sorted Set в Redis (ротация последних 100 замеров). На основе двух последних замеров вычисляется визуальный индикатор динамики здоровья: рост 📈, падение 📉 или стабильность ➡️.
8. **Подавление шума при деплоях:** CI/CD-пайплайн перед пересозданием контейнеров сам выставляет флаг `nexus:maintenance:{agent}` в Redis (с TTL — см. `deploy.yml`, переменная `MAINTENANCE_TTL_SECONDS`). Пока флаг активен, `Classifier` не пропускает сигналы о сбоях этого агента дальше в `IncidentService` — ожидаемый флап контейнера при `docker compose up -d --force-recreate` не порождает ложный инцидент. Дополнительно `StateCollector` требует `COLLECTOR_DEBOUNCE_TICKS` подряд идущих подтверждений нового статуса, прежде чем он коммитится — защита от кратковременных флапов вне контролируемых деплоев (например, ручной `docker restart`).
9. **DooD через изолированный прокси:** Ядро не монтирует напрямую сокет Docker. Запросы идут через `docker-socket-proxy`, который разрешает только безопасный whitelist методов (`inspect`, `stats`, `logs`, `restart`) и блокирует критические (например, `exec`).

## 💻 Интеграция `nexus_sdk` в ваших ботов

Интеграция занимает несколько строк в файле инициализации/запуска вашего бота.

### Вариант А. Бот на фреймворке `aiogram` (v3)
```python
import asyncio
from aiogram import Bot, Dispatcher
from nexus_sdk import NexusSDK

bot = Bot(token="TOKEN")
dp = Dispatcher()

# Инициализируем SDK
nexus = NexusSDK(
    endpoint_url="http://nexus-webhook:8000/events/app",
    app_secret="ТВОЙ_NEXUS_APP_SECRET",
    project_name="my_aiogram_bot"  # Строго совпадает с именем агента в манифестах
)

# 1. Подключаем глобальный перехватчик ошибок
nexus.register_aiogram_error_handler(dp)

# 2. Запускаем периодическую отправку пульса (Heartbeat) раз в 15 секунд
nexus.start_heartbeat(interval_seconds=15)

async def main():
    try:
        await dp.start_polling(bot)
    finally:
        await nexus.close()  # Грациозно останавливаем сессию SDK при остановке бота

if __name__ == "__main__":
    asyncio.run(main())
```

### Вариант Б. Бот на фреймворке `python-telegram-bot` (v20+)
```python
from telegram.ext import Application
from nexus_sdk import NexusSDK

app = Application.builder().token("TOKEN").build()

# Инициализируем SDK
nexus = NexusSDK(
    endpoint_url="http://nexus-webhook:8000/events/app",
    app_secret="ТВОЙ_NEXUS_APP_SECRET",
    project_name="my_ptb_bot"
)

# 1. Подключаем глобальный перехватчик ошибок PTB
nexus.register_ptb_error_handler(app)

# 2. Запускаем периодическую отправку пульса (Heartbeat)
nexus.start_heartbeat(interval_seconds=15)

def main():
    # Настройка хендлеров...
    try:
        app.run_polling()
    finally:
        # Закрываем сессию SDK при остановке приложения
        import asyncio
        loop = asyncio.get_event_loop()
        if loop.is_running():
            loop.create_task(nexus.close())
        else:
            loop.run_until_complete(nexus.close())
```

## 🔒 Модель безопасности

* **Фильтрация доступа:** Все управляющие команды, а также интерактивные inline-действия (Restart, Logs, AI Diagnose, Silence) защищены фильтром `IsAdmin` как на уровне сообщений, так и на уровне callback-запросов.
* **Безопасность Webhook-приёмника:** Все входящие запросы принимаются только при наличии валидной HMAC-SHA256 подписи в заголовках. Для GitHub-вебхуков используется `GITHUB_WEBHOOK_SECRET`, для приложений-клиентов через SDK — `NEXUS_APP_SECRET`. Отсутствие подписи или несовпадение ключа прерывают обработку на раннем этапе (fail-closed).
* **Сетевая изоляция:** Сервис вебхуков принимает входящие сигналы от ботов исключительно внутри приватной Docker-сети `nexus_shared` на хосте VPS, не открывая порты во внешний мир.
* **Docker API:** доступ идёт не напрямую через сокет, а через `docker-socket-proxy` с ограниченным набором методов. `docker exec` и управление образами через прокси недоступны в принципе.

## 📊 Математика расчёта Health Score (0–100%)

Показатель здоровья агента рассчитывается динамически на каждом тике:
* **Стартовый баланс:** `100` баллов.
* **Сбой ресурса** (`status != running/healthy`): `-50` баллов за каждый упавший компонент.
* **Критическая утилизация CPU** (>95%): `-15` баллов.
* **Критическая утилизация RAM** (>90%): `-15` баллов.
* **Каждый перезапуск контейнера** (`RestartCount`): `-5` баллов.
* **Сбой критических СУБД** (redis, postgres): дополнительный штраф `-20` баллов.

## 📡 Управление инцидентами в Telegram

* **`🔄 Restart`** — ручной перезапуск упавшего контейнера.
* **`📝 Logs`** — мгновенное извлечение последних строк кольцевого буфера логов из Redis.
* **`🧠 AI Diagnose`** — запуск ручного ИИ-анализа по агрегированному контекстному бандлу ошибки (запускается по кнопке; автоматический фоновый вызов при открытии инцидента намеренно отключён — см. «Известные ограничения»).
* **`🔕 Silence 1h`** — перевод алертов по ресурсу в режим тишины на 1 час (защита от спама при циклическом падении).

## 🛠️ Расширение системы

1. Опишите ресурсы нового бота в `agents/manifest.py`:
   ```python
   my_new_bot = ProjectAgent(
       name="my_new_bot",
       resources={
           "app": DockerContainer("app", local_transport, "my-bot-container"),
           "postgres": DockerContainer("postgres", local_transport, "my-postgres-container"),
           "data_disk": ProjectStorageResource("data_disk", local_transport, "/host_root/home/.../my_bot/data"),
           "heartbeat": ApplicationHeartbeat("heartbeat", project_name="my_new_bot"),
       }
   )
   ```
2. Зарегистрируйте его в `agents/__init__.py`: `registry.register(my_new_bot)`.
3. Добавьте точечный `:ro`-маунт под каталог данных нового проекта в сервис `nexus` в `docker-compose.yml`, не расширяя доступ шире необходимого.
4. Подключите `nexus_sdk` в коде бота (см. раздел «Интеграция `nexus_sdk`» выше), указав `project_name`, строго совпадающий с именем агента из шага 1.
5. **Если у нового бота есть собственный CI/CD-пайплайн**, добавьте в него аналогичный шаг из `deploy.yml` Nexus — выставление `nexus:maintenance:{project_name}` перед пересозданием контейнеров. Без этого деплой этого конкретного бота не будет защищён от ложных инцидентов (сейчас механизм подавления шума при деплое подключён только к самому Nexus — см. «Известные ограничения»).

Система автоматически начнёт собирать метрики, отображать реальное дисковое пространство, вычислять Health Score, показывать логи из кольцевого буфера и присылать ИИ-аналитику по запросу.

## 📌 Известные ограничения и рекомендации

* **Блокировка инцидента не имеет TTL.** `IncidentService.on_resource_failed` ставит лок через `SET NX` без `EX`. Он корректно снимается через `DELETE` при штатном событии `ResourceRecovered`, но если ресурс исчезнет из манифеста (переименован/удалён) вместо восстановления, придёт `ResourceDeleted`, на который сервис не подписан — лок останется навсегда, и при повторном появлении ресурса под тем же именем новые инциденты создаваться не будут. **Рекомендация:** добавить `ex=3600` к `SET NX` как страховочный TTL и/или подписать `IncidentService` на `ResourceDeleted`.
* **`StateCollector`** раскладывает ресурсы по `containers`/`storage`/`other`, но при восстановлении предыдущего состояния читает только `containers` и `storage` — категория `other` игнорируется. Любой кастомный `Resource`, не входящий в эти две категории, будет считаться «впервые увиденным» на каждом тике: транзитные события (`ResourceStopped`/`ResourceRecovered`/`ResourceDeleted`) для него не сработают, а `ResourceStarted`/`ResourceUnhealthy` будут публиковаться повторно на каждом тике. В `agents/manifest.py` сейчас все ресурсы явно попадают в `containers`/`storage`, поэтому баг спит, но нужно учитывать при добавлении принципиально новых типов ресурсов.
* **Подавление шума при деплое покрывает только сам Nexus.** Флаг `nexus:maintenance:{agent}` сейчас выставляется исключительно из `deploy.yml` самого репозитория Nexus (для агента `nexus`). Боты с собственными CI/CD-пайплайнами (imagebot, tarot_bot, chronicle_bot) не защищены от ложных инцидентов на их собственных деплоях, пока в их пайплайны не добавлен аналогичный шаг (см. раздел «Расширение системы»).
* **Автоматический фоновый AI-анализ при открытии инцидента отключён намеренно** — начиная с v2.0 диагностика запускается только вручную по кнопке `🧠 AI Diagnose`, чтобы не тратить токены на каждый инцидент (включая те, что закрываются авто-восстановлением за секунды) и не дублировать логику между `services/ai.py` и `telegram/notifier.py`.
* **`QueryService.get_system_status`** в ветке legacy V1-данных обращается к `res_data["status"]` без `.get()` — при повреждённом старом слепке в Redis возможен `KeyError`.
* Без собственного домена туннель работает через Cloudflare Quick Tunnel — адрес нестабилен между рестартами; синхронизация с GitHub автоматическая, но в момент смены URL возможна кратковременная потеря CI/CD-уведомления (не влияет на основной мониторинг инфраструктуры).

# 📡 Nexus (v2.0)

**Nexus** — это событийно-ориентированная платформа непрерывного наблюдения (Observability), управления и выявления скрытых угроз (AIOps) для экосистемы Telegram-ботов и сопутствующих микросервисов на вашем VPS. 

Система работает по паттерну DooD (Docker-out-of-Docker) через безопасный сокет-прокси, использует Redis для передачи оперативных сигналов (Pub/Sub) и SQLite для накопления долгосрочной SRE-статистики и обучения моделей машинного обучения.

---

## 🚀 Быстрый старт

### 1. Подготовка окружения
Склонируйте репозиторий на ваш VPS и создайте файл конфигурации `.env` на основе примера:

```bash
cp .env.example .env
```

Заполните ключевые переменные в `.env`:
* `BOT_TOKEN` — токен вашего управляющего Telegram-бота (создается через `@BotFather`).
* `ADMIN_IDS` — ваш Telegram ID (и ID других администраторов через запятую) для ограничения доступа.
* `AITUNNEL_API_KEY` — ключ доступа к API AITUNNEL (модель Google Gemma 4).
* `GITHUB_WEBHOOK_SECRET` — произвольная строка для валидации деплой-вебхуков.
* `NEXUS_APP_SECRET` — произвольный секретный ключ для верификации алертов от ваших приложений.

### 2. Запуск платформы
Nexus разворачивается одной командой с помощью Docker Compose:

```bash
docker compose up -d --build
```

После этого в вашей системе запустятся:
1. `nexus-redis` — оперативный кэш и шина событий.
2. `nexus-docker-proxy` — безопасный шлюз к API Docker Daemon.
3. `nexus-core` — основная логика сбора метрик, предиктора рисков и Telegram-интерфейса.
4. `nexus-webhook` — приемник сигналов от SDK и внешних систем (GitHub).
5. `nexus-tunnel` — автоматический туннель Cloudflare для приема вебхуков без выделенного IP-адреса.

## 🛠️ Возможности и архитектура

### 1. Интеллектуальный слой (AIOps)
* **Анализ аномалий по Z-Score:** Система отслеживает историю нагрузки каждого контейнера (CPU и RAM). При резком отклонении метрик от среднего исторического поведения (более чем на 3 стандартных отклонения) генерируется предупреждение. Встроенные лимиты безопасности (например, CPU > 35%) предотвращают ложные тревоги на низких уровнях нагрузки.
* **Прогноз рисков (CatBoost):** Ночной скрипт анализирует взаимосвязь метрик и последующих падений сервисов. Модель ИИ прогнозирует вероятность сбоя на ближайшие 30 минут.
* **Шлюз расхождения рисков (Baseline-gate):** Оповещение отправляется в Telegram только тогда, когда модель ИИ видит скрытую угрозу (например, утечку памяти), а классические правила считают систему полностью здоровой, так как жесткие пороговые лимиты еще не превышены.

### 2. Сбор и буферизация логов
Служба `LogCollector` непрерывно слушает стандартный вывод контейнеров (`docker logs -f`) и сохраняет последние строки в кольцевой буфер Redis. Это позволяет мгновенно читать логи в Telegram-интерфейсе без необходимости заходить на сервер по SSH.

### 3. Автоматическое восстановление приложений (Auto-Recovery)
Если приложение отправляет сигнал об ошибке через SDK, открывается инцидент. Если в течение заданного времени (`APP_ERROR_AUTO_RECOVERY_THRESHOLD`, по умолчанию 60 секунд) аналогичная ошибка не повторяется, Nexus автоматически закроет инцидент и зафиксирует время простоя.

## 🆕 Подключение нового проекта (Визард в Telegram)

В версии 2.0 вам больше не нужно вручную редактировать файлы конфигурации и перезапускать Nexus для добавления новых проектов.

1. Отправьте в управляющий бот команду `/newproject`.
2. Введите понятное имя проекта (например, `imagebot`).
3. Бот автоматически опросит Docker на вашем сервере и предложит список работающих контейнеров. Выберите один или несколько контейнеров кнопками.
4. Укажите путь к папке данных на хосте для мониторинга свободного места (опционально).
5. Выберите, нужно ли активировать Heartbeat-мониторинг.
6. Подтвердите настройки. Проект сохранится в локальную базу данных `data/agents.db` и мгновенно подключится к мониторингу логов и метрик в рантайме.

## 🔌 Интеграция `nexus_sdk` в ваши проекты

Для полноценного мониторинга приложений внутри ваших Telegram-ботов интегрируйте легкий SDK. Ниже приведен пример для проектов на базе **`aiogram`**:

```python
import asyncio
from aiogram import Bot, Dispatcher
from nexus_sdk import NexusSDK

bot = Bot(token="ВАШ_ТОКЕН_БОТА")
dp = Dispatcher()

# Инициализация SDK
nexus = NexusSDK(
    endpoint_url="http://nexus-webhook:8000/events/app",
    app_secret="ВАШ_NEXUS_APP_SECRET",  # Должен совпадать с указанным в .env у Nexus
    project_name="imagebot"             # Должен совпадать с именем проекта в Nexus
)

# 1. Глобальный перехват необработанных исключений
nexus.register_aiogram_error_handler(dp)

# 2. Периодическая отправка пульса (раз в 15 секунд)
nexus.start_heartbeat(interval_seconds=15)

async def main():
    try:
        await dp.start_polling(bot)
    finally:
        await nexus.close()

if __name__ == "__main__":
    asyncio.run(main())
```

## 📊 Математика здоровья (Health Score)

Показатель жизнеспособности каждого проекта рассчитывается динамически по 100-балльной шкале:
* **Базовый показатель:** `100` баллов.
* **Остановка контейнера:** `-50` баллов.
* **Остановка критической СУБД (PostgreSQL / Redis):** дополнительно `-20` баллов.
* **Нагрузка CPU > 95%:** `-15` баллов.
* **Нагрузка RAM > 90%:** `-15` баллов.
* **Автоматический перезапуск контейнера:** `-5` баллов за каждый рестарт.

Текущий тренд здоровья отображается в интерфейсе в виде стрелок (`📈`, `📉`, `➡️`) на основе сравнения последних замеров.

## 🛡️ Безопасность

* **Docker Socket Proxy:** Nexus не имеет прямого доступа к Docker-сокету хоста. Доступ изолирован через прокси-контейнер, разрешающий только чтение метрик (`stats`, `inspect`) и выполнение перезапуска (`restart`). Попытки выполнить произвольный код (`exec`) или удалить образы блокируются на сетевом уровне.
* **HMAC-SHA256 подпись:** Все внешние запросы (вебхуки от GitHub и отчеты об ошибках от SDK ваших приложений) сопровождаются криптографической подписью. Запросы без валидной подписи сбрасываются на раннем этапе (принцип *Fail-Closed*).
* **Изолированная сеть:** Эндпоинты приема алертов доступны только внутри внутренней Docker-сети `nexus_shared` и не открывают порты во внешнюю сеть хоста.

## 📈 Утилиты SRE и ML в контейнере

Для управления и анализа данных вам не требуется устанавливать зависимости (Python, Pandas, CatBoost) на сам хост-сервер. Все утилиты можно выполнять внутри запущенного контейнера.

### 1. Тренировка моделей предиктора рисков
Чтобы обновить модель прогнозирования на накопленной статистике метрик и инцидентов:
```bash
python -m pip install -r requirements-dev.txt
python scripts/train.py incident_prediction
```
*Скрипт выполнит временной сплит данных, оценит PR-AUC и сохранит модель в реестр `models/`, только если её качество превосходит предыдущую версию.*

В отдельном development/ML environment рекомендуется добавить эту задачу в системный планировщик `cron` для запуска раз в сутки (например, в 3:00 ночи):
Запускайте обучение из отдельного development/ML environment, которому доступен
`data/events.db`; production-контейнер `nexus-core` содержит только runtime-зависимости.

### 2. Офлайн-аналитика экосистемы
Быстрый ретроспективный анализ инфраструктуры без обращения к Telegram:
```bash
docker exec -it nexus-core python scripts/explore.py
```
*Выведет статистику инцидентов, топ нестабильных ресурсов по перезапускам, сводный лог критических ошибок за 24 часа и корреляцию падений серверов с недавними деплоями.*
